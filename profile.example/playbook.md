# How to read a freelance job post

1. **Diagnostics** (one line): posting age, number of proposals, payment verified, and the
   client's hire history if shown. A post older than 3 days, or with 50 or more proposals,
   is rarely worth a bid. If the post doesn't show these, list them under Open questions.
2. **Three pain points**, taken only from the client's own words. Quote or closely
   paraphrase them. Separate symptoms from root causes.
3. **One positioning angle**, grounded in the fact base. Where the job touches something
   the person hasn't done, frame it as how they would approach it, never as experience.
4. **Quickest proof of concept**: the smallest thing they could build or show before or on
   the first call. Prefer something that can be shown in a 3-minute screen recording.
5. **Fit verdict**: honest. Name gaps plainly. A good skip is worth more than a weak bid.

Rules for any proposal text drafted from this:
- Open on the client's problem, not the person's background.
- No invented metrics, clients or case studies.
- At least one insight the client didn't write themselves (a hidden risk, a sequencing call).
- End with a question, not a sales pitch.
